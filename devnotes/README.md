Why does this exist?

This mainly exists so we can run MAME 3D games inside Age of Joy, a VR/MR virtual arcade. Age of Joy is a Meta Quest 2/3 native app that gives you an empty arcade and lets you fill it up with user-created cabinets. Emulation is handled through Retroarch cores.

While the Quest 2/3 are able to handle older games, the strain the software rendering of modern MAME puts on the CPU makes games choppy or unplayable. The solution is to make a custom core where we rewrite MAME's renderer to use Vulkan, and we magically hit frame rate. The core also gives us the ability to add some 

This is based on MAME, is not as good as MAME and never will be. It will have the same issues as MAME (if not more). It exists for QOL additions and playability on niche hardware, not for preservation or accuracy. It's also going to be behind MAME and even though I'll try to stay on top of rolling in the latest fixes from the main MAME branch, so if I get hit by a bus it's probably not gonna to get updated. I'm old as dirt anyway.

COOL STUFF THIS DOES
Again, the Good Stuff of this core is offloading the rendering to the GPU in Vulkan. I spent a few months hacking on Model 2 stuff and figuring out how to get past the Painter's Algorithm on a separate project, so I rolled that into this and the rendering's pretty good! ElSemi had all of this sorted over 15 years ago with his Model 2 Emulator for Windows so this is in no way a flex.

| [ppmdiff.py](ppmdiff.py) | **The A/B measurement after `cmp` stopped working** (P3 step 3, rebuilt at step 7). `coverage` calls a pixel drawn when it differs from an `M2VK_NO_3D=1` reference — which both renderers still produce bit-identically — and reports drawn-or-not agreement plus how much of the disagreement is on a polygon edge. `exact` is exit criterion 1. `ssim` is exit criterion 2, scored over the covered region only. `heatmap` writes the picture behind the numbers. `report` runs all four. Needs numpy; the PNG writer is stdlib. |

Requires the `M2VK_NO_3D=1` background to come back bit-identical at every scale before it measures anything, and refuses a run whose log carries no `supersample:` line. 🚨 **`POINT=1` with an ODD scale is the run that carries an invariance claim** — a box resolve moves the sample points, so it can gain *and lose* sub-sample-width geometry, and `res.sh` only enforces `ppmdiff`'s interior verdict on point runs. |

## Conventions
- **Finishing a step means writing it down.** Three files, every time: an entry in `worklog.md`, the
  step struck through in the phase's plan file with what was *actually* built, and `CLAUDE.md`'s
  "Where we are" + **"Next step"** brought current. A stale "Next step" costs the next session real
  work. Full version in the commit-hygiene half of `CLAUDE.md`.
- One topic per file, kebab-case names.
- Date-stamp entries in `worklog.md` (absolute dates, not "yesterday").
- Cite code as `path:line` against **mame0288** — line numbers drift on upstream merges, so also
  quote enough of the symbol name to re-find it.
